# Пишем технический блог на Markdown и оптимизируем SEO

Писать технический блог на Markdown — самый эффективный подход, но чтобы поисковые системы его полюбили, нужно выполнить «стандартные SEO-движения». Ниже — применимый на практике процесс.

## 1. Контент как данные: SEO через frontmatter

Для каждой статьи объявляйте заголовок, описание, ключевые слова и дату в YAML frontmatter:

```yaml
title: "Article title"
description: "A one-sentence summary that appears in search results"
keywords: ["keyword one", "keyword two"]
pubDate: 2026-07-25
```

Эти поля автоматически внедряются в `<title>`, `<meta name="description">` и `<meta name="keywords">` — без ручного редактирования HTML.

## 2. Три основы SEO

| Основа | Назначение |
| --- | --- |
| `sitemap.xml` | Сообщает краулерам, какие страницы существуют |
| `robots.txt` | Направляет краулеры и ссылается на карту сайта |
| `JSON-LD` | Описывает статью структурированными данными (автор, дата, ключевые слова) |

## 3. Карточки для соцсетей

Настройте Open Graph и Twitter Card, чтобы при публикации в WeChat, X, Telegram и других сетях у статей появлялась красивая превью-картинка.

## 4. Скорость — это ранжирование

Статические сайты по умолчанию не отправляют JS времени выполнения и загружаются мгновенно — природное преимущество для SEO. В сочетании с CDN/edge-сетью (например, Cloudflare Pages) для глобального ускорения показатели Core Web Vitals легко достигаются.

## 5. Контент под управлением Git

Статьи блога — это просто файлы `.md` в репозитории:

- Изменить контент = изменить файл + открыть PR
- Опубликовать = слить и задеплоить автоматически
- История = лог коммитов Git

Такой подход «контент как код» делает технический блог и лёгким в написании, и лёгким в поддержке.
