# Markdown から PDF へ：完全ガイド

Markdown はその最小限のプレーンテキスト記法で広く親しまれ、PDF はクロスプラットフォームで固定レイアウトの「最終成果物」です。両者を組み合わせるのは、ライター、開発者、運用担当者の日常的な要件です。本記事では **Markdown から PDF** へのいくつかの手法とトレードオフを体系的に解説します。

## なぜ Markdown を PDF に変換するのか

- **執筆に集中できる**：Markdown ならフォーマットを気にせず、内容だけに集中できます。
- **安定的な納品**：PDF はどのデバイスでもレイアウトが一致し、契約書や履歴書、ドキュメントに最適です。
- **バージョン管理できる**：ソースはプレーンテキストなので、Git との相性が抜群です。

## 3 つの主なアプローチ

### 1. ブラウザ印刷（最も正確）

Markdown を HTML に変換し、ブラウザの「印刷 → PDF として保存」を使います。長所：スタイルが 100% 一致、依存なし、無料。これが本ツールの「印刷 / PDF として保存」ボタンの背後にある仕組みです。

### 2. フロントエンドライブラリでワンクリック書き出し（最も手軽）

`html2pdf.js`（`html2canvas` + `jsPDF` をラップ）を使って、ページを直接 PDF ファイルに変換します。長所はワンクリックでダウンロードできることですが、複雑な CSS（改ページや背景など）はわずかにずれることがあります。

### 3. コマンドライン（バッチに最適）

`pandoc`、`mdpdf`、`weasyprint` など。CI でのバッチ生成に向いていますが、環境構築が必要です。

## レイアウトのベストプラクティス

1. `@page { size: A4; margin: 16mm; }` で印刷の余白を制御します。
2. コードブロックは等幅フォントを使い、配色を維持して読みやすさを高めます。
3. 長い表には `pagebreak` ルールを使って切れ目を防ぎます。
4. 幅をピクセルで固定せず、PDF がページに適応するようにします。

## まとめ

**完全な一致**を求めるならブラウザ印刷を、**ワンクリックダウンロード**を求めるならフロントエンドライブラリを使います。本ツールは両方を用意しています——左に Markdown を書けば、右に A4 レイアウトがリアルタイムで表示され、そのまま書き出せます。
